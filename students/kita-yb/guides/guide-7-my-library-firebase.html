איך נראית עצירת "אימות הבנה"

לאורך המדריך תפגשו תיבות כאלה:

אימות הבנה עם המורהדוגמה

בכל תיבה שתי משימות. קודם עונים לעצמכם, ורק אז קוראים למורה ומסבירים בעל-פה, בלי להסתכל במדריך:

  • הסבירו מה הקוד הזה עושה: קטע קוד קצר, לפעמים עם טעות. מה יקרה כשהוא ירוץ, ולמה.
  • דרישה חדשה: מי שהזמין את האפליקציה ביקש שינוי. הסבירו איך הייתם מתאימים את הפתרון: מה הייתם משנים, ובאיזה קובץ. לא צריך לכתוב את הקוד, צריך לדעת להסביר.

לכל נקודת אימות יש מספר, למשל נקודת אימות 3. המורה רושם אצלו לפי המספר, אז כשאתם קוראים למורה, אמרו את מספר הנקודה.

המדריך נפתח בהדרגה

אחרי כל אחת מנקודות האימות 1 עד 7, ההמשך של המדריך נעול. אחרי השיחה המורה ייתן לכם קוד בן 5 תווים, ואתם מקלידים אותו בתיבה שמתחת לנקודה. אחרי נקודה 7 נפתח כל ההמשך. גם בנקודות האימות של ההרחבות ושל המסלול המתקדם מקבלים קוד מהמורה, אבל שם הוא לא נועל כלום: הוא רק רושם שעברתם.

כל קוד נכון נרשם אוטומטית בטבלה של המורה, עם השם שלכם והשעה.

  • בפעם הראשונה תתבקשו להקליד את שמכם: שם פרטי ושם משפחה בלבד, בלי שם שני. למשל: ישראל ישראלי. המורה מקליד בטלפון שלו בדיוק את אותו שם.
  • רשמו כל קוד במחברת. אם תעבדו בשיעור הבא על מחשב אחר, תקלידו את הקודים שוב כדי לפתוח את מה שכבר עברתם.
  • בסוף שיעור במחשב של הכיתה לחצו "סיום עבודה במחשב הזה" בתחתית הדף, כדי שהתלמיד הבא לא ימשיך מהמקום שלכם.

מה צריך לפני שמתחילים

חשבון Google אישי (Gmail), שאתם יודעים את הסיסמה שלו. Firebase הוא שירות של Google, ונכנסים אליו עם חשבון Google. אין צורך בכרטיס אשראי: כל מה שנעשה במדריכים האלה נמצא בתוכנית החינמית של Firebase, שנקראת Spark.

חלק 1

חזרה: טופס עם שדות קלט

איפה עובדים: Android Studio
  1. צרו פרויקט חדש בשם MyLibrary. תבנית Empty Views Activity, שפה Java, ‏Minimum SDK ‏API 26, ‏Build configuration language ‏Groovy DSL.
  2. חובה, לפני שמוסיפים רכיב כלשהו: פתחו את activity_main.xml במצב Code, מחקו את כל התוכן שלו והדביקו במקומו את שלד ה-LinearLayout שמופיע מתחת לרשימה.
  3. בתוך השלד: TextView בשם (id) tvTitle עם הטקסט "הספרייה שלי" (גודל 28sp, ממורכז).
  4. מתחתיו שלושה שדות קלט: EditText בשם (id) etBook עם hint "שם הספר", EditText בשם (id) etAuthor עם hint "שם הסופר", ו-EditText בשם (id) etPages עם hint "מספר עמודים". בחרו לכל שדה את ה-inputType המתאים, ולשדה העמודים הגבילו את האורך ל-4 ספרות.
  5. מתחת לשדות: כפתור בשם (id) btnSave עם הטקסט "שמירה בענן", כפתור בשם (id) btnLoad עם הטקסט "טעינה מהענן", ו-TextView בשם (id) tvStatus עם הטקסט "עוד לא נשמר כלום" (גודל 18sp, ממורכז).
  6. לחיצה על btnSave בודקת שאף שדה לא ריק. שדה ריק מסומן ב-setError, והבדיקה נעצרת. אם הכול תקין, מוצג Toast "הנתונים תקינים". את השמירה בענן נוסיף בהמשך.
  7. הריצו ובדקו.

האזהרה Extraneous text in resource files אומרת שנשארו תווים מיותרים מחוץ לתגיות.

רמז: איזה inputType לכל שדה

לשם הספר ולשם הסופר: text. למספר העמודים: number, ובנוסף android:maxLength="4".

רמז: הבדיקה של מספר העמודים

זה בדיוק מה שעשיתם במחשבון הממוצע: קודם בודקים isEmpty(), ורק אחר כך ממירים למספר עם Integer.parseInt. אחרי setError בא return. את המספר pages נשמור בענן בהמשך.

String pagesText = etPages.getText().toString();
if (pagesText.isEmpty()) {
    etPages.setError("חובה למלא מספר עמודים");
    etPages.requestFocus();
    return;
}
int pages = Integer.parseInt(pagesText);
סיימתם את החזרה כש...

שדה ריק מסומן באדום, והבדיקה נעצרת בשדה הראשון שיש בו בעיה. כשהכול תקין מופיע "הנתונים תקינים". קראו למורה לרישום 5 הנקודות, ובאותה הזדמנות עברו את שתי עצירות אימות ההבנה של החזרה.

נקודת אימות 1אימות הבנה עם המורה: שדות קלט5 נק'

הסבירו מה הקוד הזה עושה. בשדה העמודים מוגדר inputType="number". תלמיד אמר: "בגלל זה אין צורך לבדוק אם השדה ריק, הוא תמיד מכיל מספר". האם הוא צודק? מה יקרה בשורה הבאה כשהמשתמש לא הקליד כלום?

int pages = Integer.parseInt(etPages.getText().toString());

דרישה חדשה. רוצים להוסיף שדה "ז'אנר" (מדע בדיוני, מתח וכדומה). איזה inputType תבחרו, ואיזו בדיקה הוא צריך?
