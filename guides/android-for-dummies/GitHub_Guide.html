הסבר

מה זה Git, ומה זה GitHub

עד היום הפרויקט שלכם היה תיקייה במחשב אחד. אם המחשב התקלקל, הפרויקט נעלם. אם עבדתם בבית, הייתם צריכים להעביר קבצים בדיסק-און-קי או במייל. ואם שברתם משהו שעבד אתמול, לא הייתה דרך לחזור לגרסה של אתמול.

שני כלים פותרים את זה:

Git: נקודות שמירה, כמו במשחק

במשחק מחשב אתם שומרים לפני קרב קשה. אם הפסדתם, חוזרים לנקודת השמירה. Git עושה את זה לקוד. כל נקודת שמירה נקראת commit, ולכל אחת מצרפים משפט קצר שמתאר מה השתנה, כמו שם לשמירה במשחק. Git זוכר את כל השמירות, ואפשר לחזור לכל אחת מהן.

תיקיית פרויקט ש-Git שומר עליה נקראת repository, או בקיצור repo. בעברית: מאגר. זו תיקייה רגילה, שיש לה גם "מכונת זמן".

GitHub: הענן של נקודות השמירה

GitHub הוא אתר שמחזיק עותק של המאגר שלכם בענן, כמו Google Drive, אבל עם כל ההיסטוריה. אתם עובדים במחשב, ומדי פעם מסנכרנים עם הענן בשני כיוונים:

מילהמה זהמהחיים
repositoryתיקיית הפרויקט, עם כל ההיסטוריה שלהתיקייה עם מכונת זמן
commitנקודת שמירה עם תיאורשמירה במשחק

cloneהורדה ראשונה של כל המאגר למחשב חדשהתקנת משחק בטלפון חדש והתחברות לחשבון: כל ההתקדמות חוזרת
branchענף: עותק צדדי לניסויטיוטה של פוסט: עובדים עליה בלי שאף אחד רואה

Git מול GitHub, במשפט אחד

Git הוא התוכנה במחשב ששומרת נקודות. GitHub הוא האתר שמחזיק אותן בענן. Android Studio יודע לדבר עם שניהם, כך שכמעט לא תצטרכו לצאת ממנו.

שלב 1

פותחים חשבון GitHub

1

הרשמה

  1. היכנסו ל-github.com/signup.
  2. הזינו את המייל האישי שלכם, וסיסמה חזקה שלא משמשת אתכם באף אתר אחר.
  3. בחרו שם משתמש. הוא יופיע בכתובת של כל הפרויקטים שלכם, למשל github.com/dana-dev. בחרו שם שלא תתביישו בו בעוד שלוש שנים, כשתשלחו אותו למעסיק או ליחידה בצבא.
  4. פתרו את הפאזל, ואשרו את הקוד שנשלח למייל.
  5. אם GitHub שואל שאלות על התוכנית או על השימוש, אפשר לדלג. התוכנית החינמית (Free) מספיקה.
הסיסמה שלכם בלבד

שמרו אותה במקום בטוח, לא על פתק ליד המחשב. מי שיש לו את הסיסמה יכול למחוק את כל הפרויקטים שלכם.

אימות דו-שלבי

GitHub מחייב משתמשים שמעלים קוד להפעיל אימות דו-שלבי, ויבקש את זה מכם תוך כמה שבועות מפתיחת החשבון. תצטרכו אפליקציית אימות בטלפון. כשההודעה תופיע, עשו את זה עם המורה, ושמרו את קודי השחזור שתקבלו.

אתם מחוברים ל-GitHub באתר. קראו למורה לרישום 10 הנקודות.

שלב 2

פרויקט HelloGit והכנת Android Studio

1

יוצרים פרויקט

צרו פרויקט חדש בשם HelloGit. הכול כרגיל: תבנית Empty Views Activity, שפה Java, ‏Minimum SDK ‏API 26, ‏Build configuration language ‏Groovy DSL.

ב-activity_main.xml מצאו את ה-TextView הקיים, ושנו את הטקסט שלו ל-"Hello GitHub!". הריצו ובדקו שהמשפט מופיע. זה כל הקוד שתכתבו היום.

2

בודקים ש-Git מותקן, ומתקינים מתוך Android Studio אם צריך

Android Studio משתמש בתוכנת Git שמותקנת במחשב. ייתכן שבמחשב שקיבלתם היא עוד לא מותקנת. בודקים:

  1. בתפריט העליון: File > Settings.
  2. בתיבת החיפוש בפינה השמאלית העליונה כתבו Git, ובחרו בצד את Version Control > Git.
  3. מצאו את השדה Path to Git executable. לא כותבים בו כלום, ולא מסמנים את Set this path only for the current project. רק מסתכלים על השורה שמתחת לשדה.

אם בשדה כתוב באפור Auto-detected, ומתחתיו Git version is עם מספר, כמו בציור: Git מותקן, ו-Android Studio מצא אותו לבד. הטקסט האפור הוא לא משהו שצריך להקליד. לחצו OK ועברו לצעד הבא.

אם מתחת לשדה מופיעה הודעה ש-Git לא נמצא, ולידה קישור Download and Install: לחצו על הקישור. Android Studio יוריד את Git ויתקין אותו בעצמו. ההורדה לוקחת דקה או שתיים, ובזמן הזה רואים פס התקדמות בתחתית החלון. בסיום, ורק אז, לחצו על הכפתור Test שליד השדה: הוא בודק מחדש אם Git נמצא. וודאו שמתחת לשדה מופיע עכשיו Git version is עם מספר.

אחרי התקנה: סגרו ופתחו מחדש את Android Studio

בצעד הבא כותבים פקודה בטרמינל. טרמינל שנפתח לפני ההתקנה לא תמיד יודע ש-Git קיים. File > Exit, ופתחו את Android Studio שוב, עם הפרויקט HelloGit.

3

מגדירים שהענף הראשי ייקרא main

לגרסה הראשית של הפרויקט קוראים main. במחשבים מסוימים Git קורא לה בשם הישן, master. כדי שכולם בכיתה יראו אותו דבר, מגדירים את זה פעם אחת.

בתחתית הסרגל השמאלי של Android Studio לחצו על סמל ה-Terminal (מלבן עם >_). בחלון שנפתח כתבו את השורה הבאה ולחצו Enter:

git config --global init.defaultBranch main
מה עשינו פה

כתבנו פקודה ישירות ל-Git. זו הפעם היחידה במדריך שבה מקלידים פקודה "גלובלית", כלומר כזו שחלה על כל המחשב. היא לא מזיקה לאף אחד, ולכן מותר להשאיר אותה.

הטרמינל כותב ש-git לא מוכר?

אם מופיעה הודעה כמו 'git' is not recognized: חזרו לצעד 2 וודאו שמתחת לשדה מופיע מספר גרסה. אם כן, סגרו ופתחו מחדש את Android Studio ונסו שוב. אם זה עדיין לא עובד, קראו למורה לפני שממשיכים.

4

מתחברים לחשבון מתוך Android Studio

  1. בתפריט העליון: File > Settings.
  2. בתיבת החיפוש בפינה השמאלית העליונה של החלון כתבו GitHub, ובחרו בצד את Version Control > GitHub (שורה אחת מתחת ל-Git מהצעד הקודם).
  3. לחצו על + ובחרו Log In via GitHub....
  4. הדפדפן ייפתח. אם צריך, התחברו לחשבון. יופיע מסך שמבקש אישור עבור JetBrains IDE Integration: ‏JetBrains היא החברה שבנתה את הבסיס של Android Studio ואת החיבור שלו ל-GitHub. לא צריך להירשם אליה או לפתוח שום חשבון נוסף. לחצו Authorize.
  5. חזרו ל-Android Studio. שם המשתמש שלכם מופיע עכשיו ברשימה. לחצו OK.
מופיע ברשימה חשבון של מישהו אחר?

זה אומר שהתלמיד הקודם לא יצא מהחשבון. סמנו את החשבון שלו, לחצו - כדי להסיר אותו, ורק אז הוסיפו את שלכם. ספרו למורה.

סיימתם את השלב כש...

האפליקציה מציגה "Hello GitHub!", ב-Settings > Version Control > Git מופיע מספר גרסה מתחת לשדה, וב-Settings > Version Control > GitHub מופיע החשבון שלכם בלבד. קראו למורה לרישום 10 הנקודות.

שלב 3

העלאה ראשונה: Share Project on GitHub

עכשיו הופכים את תיקיית הפרויקט למאגר, ומעלים אותו ל-GitHub. Android Studio עושה את שני הדברים בפעולה אחת.

1

פותחים את חלון השיתוף

בתפריט העליון לחצו VCS, ובחרו Share Project on GitHub:

VCS
Enable Version Control Integration...
Get from Version Control...
Create Git Repository...
Share Project on GitHubלבחור את זו

בחלון שנפתח:

  • Repository name: HelloGit
  • Private: לא מסומן. המאגר ציבורי, כדי שהמורה יוכל לראות אותו.
  • Share by: החשבון שלכם. ודאו שזה באמת שלכם.
  • Description: משפט קצר באנגלית, למשל My first GitHub practice.

לחצו Share.

ב-GitHub כותבים רק באנגלית

שם המאגר, התיאור, הודעות ה-commit ושמות הענפים: הכול באנגלית. כך עובדים מתכנתים בכל העולם, ועברית בשמות של ענפים וקבצים גם עלולה לגרום לתקלות. זה כלל לכל השנה, לא רק במדריך הזה.

2

בוחרים מה עולה

ייפתח חלון Add Files For Initial Commit עם רשימת הקבצים. אל תשנו כלום. השאירו את ההודעה Initial commit ולחצו Add.

למה לא כל הקבצים ברשימה?

בפרויקט יש קובץ בשם .gitignore, ש-Android Studio יצר בשבילכם. הוא רשימה של מה לא לארוז: קבצים זמניים שהמחשב יוצר לבד בכל בנייה, והגדרות שמתאימות רק למחשב הזה. כמו שלא אורזים את המקרר כשנוסעים לטיול: במקום החדש כבר יש אחד.

Android Studio שואל על שם ומייל?

אם קופץ חלון שמבקש Name ו-Email: כתבו את השם שלכם ואת המייל שאיתו נרשמתם ל-GitHub, ובטלו את הסימון ב-Set properties globally. אחר כך המשיכו.

3

בודקים באתר

אחרי כמה שניות תופיע בפינת המסך הודעה Successfully shared project on GitHub, עם קישור. לחצו עליו, או היכנסו לאתר GitHub ופתחו את המאגר HelloGit.

אתם אמורים לראות את תיקיות הפרויקט: app, gradle, וקבצים כמו build.gradle. היכנסו ל-app/src/main/res/layout/activity_main.xml ומצאו את "Hello GitHub!".

התפריט VCS השתנה לשם Git

מעכשיו, בפרויקט הזה, במקום התפריט VCS מופיע תפריט בשם Git. כל הפעולות של המדריך נמצאות בו.

סיימתם את השלב כש...

באתר GitHub, בכתובת github.com/שם-המשתמש/HelloGit, רואים את קובצי הפרויקט. הראו למורה את הדף לרישום 15 הנקודות.

שלב 4

commit ו-push: שומרים ומעלים

זו הפעולה שתעשו הכי הרבה פעמים השנה: משנים משהו, שומרים נקודה, ומעלים אותה לענן. את כל הפעולות עושים ב-Android Studio. לאתר GitHub בדפדפן נכנסים רק כדי לבדוק מה הגיע לענן.

1

משנים משהו

איפה: Android Studio

ב-activity_main.xml שנו את הטקסט ל-"Hello GitHub! My name is ..." עם השם שלכם, והוסיפו android:textSize="24sp". הריצו ובדקו.

שימו לב: שם הקובץ בעץ הקבצים ובלשונית למעלה צבוע עכשיו בכחול. כך Android Studio מסמן קובץ שהשתנה מאז נקודת השמירה האחרונה.

2

commit: נקודת שמירה

איפה: Android Studio
  1. לחצו Ctrl+K, או בתפריט Git > Commit.... בצד שמאל ייפתח חלון Commit.
  2. ברשימה מופיע activity_main.xml, מסומן. לחיצה כפולה עליו מראה מה בדיוק השתנה: משמאל הגרסה הקודמת, מימין החדשה.
  3. בתיבת ההודעה כתבו מה עשיתם, למשל: Add my name and bigger text.
  4. לחצו Commit (לא Commit and Push, את זה נעשה בצעד הבא בנפרד).
הודעה טובה, הודעה גרועה

"שינויים", "עדכון" או "asdf" לא יעזרו לכם בעוד חודש, כשתחפשו מתי שברתם משהו. הודעה טובה עונה על השאלה "מה השתנה?" במשפט קצר: "Add reset button", "Fix crash on empty name". כמו שם לשמירה במשחק: "לפני הבוס של שלב 3" עדיף על "שמירה 17".

שם הקובץ ב-Android Studio חזר לצבע רגיל: אין שינויים שלא נשמרו. אבל הנקודה עדיין רק במחשב.

איפה: אתר GitHub בדפדפן

עברו לדפדפן, לדף המאגר HelloGit, ורעננו אותו (F5). פתחו את activity_main.xml: הטקסט שם עדיין הישן, כי עוד לא העליתם כלום.

3

push: מעלים לענן

איפה: Android Studio
  1. לחצו Ctrl+Shift+K, או בתפריט Git > Push....
  2. בחלון מופיעה רשימת הנקודות שעוד לא עלו לענן. אמורה להיות אחת: זו שיצרתם עכשיו.
  3. לחצו Push.
איפה: אתר GitHub בדפדפן

חזרו לדפדפן ורעננו את דף המאגר. ליד שם הקובץ מופיעה עכשיו ההודעה שכתבתם. עכשיו פתחו את ההיסטוריה: לחצו על הכפתור עם סמל השעון. אם אתם בתוך דף של קובץ, למשל activity_main.xml, הוא נקרא History, ומציג את ההיסטוריה של הקובץ הזה. בדף הראשי של המאגר הוא נקרא Commits, ומציג את ההיסטוריה של כל הפרויקט. בשני המקרים תראו את נקודות השמירה שלכם, כל אחת עם ההודעה שכתבתם.

סיימתם את השלב כש...

באתר רואים את הטקסט החדש, ובהיסטוריה יש שני commits. עכשיו עברו את אימות ההבנה.

אימות הבנה עם המורה: commit ו-pushחלק מ-15 הנקודות

הסבירו מה קרה כאן. תלמיד עבד כל השיעור, עשה חמישה commits עם הודעות טובות, וסגר את המחשב. בבית הוא פתח את המאגר באתר GitHub, ולא מצא שם אף אחד מהשינויים של היום. מה הוא שכח? האם העבודה שלו אבדה? מה הוא צריך לעשות בשיעור הבא, ובאיזה מחשב?

דרישה חדשה. אתם עומדים לשנות משהו גדול במסך, ולא בטוחים שזה יעבוד. איך תשתמשו ב-commit כדי שתוכלו לחזור לגרסה שעבדה, ומתי בדיוק תעשו אותו?

שלב 5

pull: מקבלים שינוי שנעשה במקום אחר

בבית תעבדו על מחשב אחר, ובשיעור הבא תצטרכו להוריד את מה שעשיתם שם. כדי לתרגל את זה בכיתה, בלי מחשב שני, נשתמש באתר GitHub עצמו בתור "המחשב האחר".

1

משנים באתר

  1. באתר GitHub, במאגר HelloGit, היכנסו ל-app/src/main/res/layout/activity_main.xml.
  2. לחצו על סמל העיפרון (Edit this file) בפינה של תוכן הקובץ.
  3. שנו את הטקסט ל-"Hello from home!".
  4. לחצו Commit changes..., כתבו הודעה (Change text from home), ובחרו Commit directly to the main branch. לחצו שוב Commit changes.

עכשיו בענן יש נקודת שמירה שאין במחשב. ב-Android Studio הטקסט עדיין הישן.

2

pull: מורידים

  1. ב-Android Studio לחצו Ctrl+T, או בתפריט Git > Update Project....
  2. אם נפתח חלון שאלות, בחרו Merge ולחצו OK.
  3. פתחו את activity_main.xml. הטקסט הוא עכשיו "Hello from home!". הריצו ובדקו.
Update Project ו-Pull

ב-Android Studio הפעולה נקראת Update Project. מאחורי הקלעים היא עושה pull: מורידה מהענן את כל מה שחסר במחשב.

הכלל הכי חשוב בכל המדריך

pull בתחילת העבודה, push בסוף העבודה. אם תתחילו לשנות קוד לפני pull, בזמן שבענן יש גרסה חדשה יותר, Git יצטרך למזג שתי גרסאות שונות של אותו קובץ. זה פתיר, אבל מבלבל ולוקח זמן. הרגל של חמש שניות בתחילת שיעור חוסך את זה.

סיימתם את השלב כש...

הטקסט שנכתב באתר מופיע באפליקציה שרצה במחשב. עכשיו עברו את אימות ההבנה.

אימות הבנה עם המורה: pullחלק מ-15 הנקודות

הסבירו מה קרה כאן. תלמידה עבדה בבית ועשתה push. בכיתה היא פתחה את הפרויקט שנשאר על המחשב מהשבוע שעבר, ומיד התחילה לשנות קוד, בלי pull. כשניסתה לעשות push בסוף השיעור, Android Studio סירב ואמר שבענן יש שינויים שאין אצלה. למה Git עוצר אותה? מה הייתה הדרך לחסוך את זה?

דרישה חדשה. מעכשיו תעבדו כל שבוע בשלושה מקומות: בכיתה, בבית, ולפעמים במחשב של סבתא. כתבו למורה את הסדר המדויק של הפעולות שלכם, מרגע שאתם מתיישבים מול מחשב ועד שאתם קמים.

שלב 6

clone: הפרויקט במחשב חדש

במחשב שהפרויקט עוד לא נמצא עליו, למשל מחשב נייד אחר בכיתה, אין מה למשוך. צריך להוריד את כל המאגר בפעם הראשונה. לזה קוראים clone. כאן נדמה מחשב חדש על ידי הורדה לתיקייה חדשה.

1

סוגרים ומורידים

  1. סגרו את הפרויקט: File > Close Project. נפתח מסך הפתיחה של Android Studio.
  2. במסך הפתיחה לחצו Clone Repository, או בתוך פרויקט: VCS > Get from Version Control....
  3. בצד שמאל של החלון בחרו GitHub. מופיעה רשימת המאגרים שלכם. בחרו HelloGit.
  4. בשדה Directory בסוף הנתיב שנו את שם התיקייה ל-HelloGit2, כדי שלא תדרוס את המקורית.
  5. לחצו Clone. אם נשאלים אם לסמוך על הפרויקט, בחרו Trust Project.
  6. חכו שהסנכרון של Gradle יסתיים (פס ההתקדמות למטה), והריצו.
2

אומרים ל-Git מי אתם, בפרויקט הזה

המחשבים הניידים בכיתה משותפים. כדי שה-commits שלכם יירשמו על שמכם ולא על שם התלמיד הקודם, מגדירים את השם והמייל בתוך הפרויקט בלבד. פתחו את ה-Terminal וכתבו, כל שורה ואחריה Enter (עם השם שלכם והמייל שאיתו נרשמתם ל-GitHub, בתוך המירכאות):

git config user.name "Dana Levi"
git config user.email "dana.levi@gmail.com"

כדי לבדוק, כתבו git config user.name. אמור להופיע השם שלכם.

בלי המילה --global

בשלב 2 השתמשנו ב---global, וזה היה בסדר כי ההגדרה לא אישית. כאן לא כותבים --global, כי במחשב משותף השם שלכם היה נרשם גם על העבודה של התלמיד הבא.

סיימתם את השלב כש...

הפרויקט HelloGit2 פתוח, רץ, ומציג "Hello from home!", ו-git config user.name מחזיר את השם שלכם. קראו למורה לרישום 10 הנקודות.

שלב 7

ענף זמני: שינוי זהיר בלי לסכן את main

עד עכשיו עבדתם ישר על main, הגרסה הראשית. רוב הזמן זה מה שתעשו. אבל כשאתם עומדים לנסות משהו שעלול לשבור את הפרויקט, עדיף לנסות אותו בצד. אם הניסיון מצליח, מעבירים אותו ל-main. אם לא, זורקים אותו, ו-main נשאר שלם.

1

יוצרים ענף

  1. בסרגל העליון, ליד שם הפרויקט, מופיע שם הענף הנוכחי: main. לחצו עליו. (אם לא מוצאים: Git > Branches....)
  2. בחרו New Branch....
  3. שם: try-color. ודאו ש-Checkout branch מסומן, ולחצו Create.

בסרגל העליון כתוב עכשיו try-color: אתם עובדים בענף הצדדי.

2

משנים ושומרים בענף

הוסיפו ל-TextView את השורה android:textColor="#C62828", הריצו ובדקו שהטקסט אדום. עשו commit עם ההודעה Try red text.

ניסוי של דקה: לחצו על שם הענף בסרגל העליון, בחרו main ואז Checkout. הריצו. הטקסט שחור! השינוי קיים רק בענף. חזרו לענף try-color באותה דרך.

3

ממזגים ל-main, מעלים ומוחקים את הענף

הניסיון הצליח. מעבירים אותו לגרסה הראשית:

  1. חזרו ל-main: שם הענף בסרגל העליון, main, Checkout.
  2. שוב לחצו על שם הענף. בחרו try-color, ואז Merge 'try-color' into 'main'.
  3. הריצו: עכשיו הטקסט אדום גם ב-main.
  4. עשו push (Ctrl+Shift+K), ובדקו באתר שהשינוי הגיע.
  5. מחקו את הענף שכבר לא צריך: שם הענף בסרגל העליון, try-color, Delete.
מתי מוחקים, ומתי לא

מוחקים ענף רק אחרי שמיזגתם אותו ל-main ובדקתם שהכול עובד. ואם הניסיון נכשל? חוזרים ל-main ומוחקים את הענף בלי למזג. main לא נפגע בכלל.

סיימתם את השלב כש...

הטקסט אדום באתר GitHub, ב-main, ונשאר רק ענף אחד: main. עכשיו עברו את אימות ההבנה.

אימות הבנה עם המורה: ענף זמניחלק מ-10 הנקודות

הסבירו מה קרה כאן. תלמיד יצר ענף new-design, עבד בו שעה, עשה commit ו-push, וראה ב-GitHub שה-push הצליח. אבל כשפתח את האפליקציה בבית אחרי pull, העיצוב הישן חזר. איפה העבודה שלו? מה הוא לא עשה?

דרישה חדשה. בעוד שבוע תוסיפו לפרויקט הגמר מסך מסובך, שאתם לא בטוחים שיעבוד. תארו למורה את כל הצעדים, מיצירת הענף ועד מחיקתו, כולל מה תעשו אם אחרי שעתיים יתברר שהרעיון לא עובד.

שלב 8

יציאה מהחשבון וניקוי המחשב

המחשבים הניידים בכיתה עוברים מיד ליד, וכולם עובדים תחת אותו משתמש Windows. אם לא תצאו מהחשבון, התלמיד הבא יוכל להעלות קוד לחשבון שלכם, או למחוק בו דברים. זה כמו להשאיר את האינסטגרם שלכם פתוח בטלפון של חבר.

את ארבעת הצעדים עושים בסוף כל שיעור, ולפי הסדר. קודם מוודאים שהעבודה בענן, ורק אז מוחקים.

1

מוודאים שהכול בענן

  1. אין קבצים בכחול או באדום בעץ הקבצים. אם יש, עשו commit.
  2. עשו push. אם Android Studio אומר שאין מה להעלות, מצוין.
  3. באתר GitHub, ודאו שה-commit האחרון שלכם מופיע בראש רשימת הקבצים.
2

מסירים את החשבון מ-Android Studio

  1. File > Settings, חיפוש GitHub, ובחירה ב-Version Control > GitHub.
  2. סמנו את החשבון שלכם ולחצו - (הסרה). הרשימה צריכה להיות ריקה.
  3. OK.
3

מוחקים את הסיסמאות השמורות ב-Windows

Windows שומר עותק של פרטי ההתחברות גם מחוץ ל-Android Studio.

  1. לחצו על מקש Windows והקלידו Credential Manager (בעברית: מנהל האישורים). פתחו אותו.
  2. בחרו Windows Credentials (אישורי Windows).
  3. עברו על הרשימה תחת Generic Credentials. כל שורה שמופיעה בה המילה github, למשל git:https://github.com: לחצו עליה, ואז Remove (הסר), ואשרו.
  4. בדקו שוב: לא נשארה אף שורה עם github.
4

מתנתקים בדפדפן ומוחקים את הפרויקט מהמחשב

  1. באתר GitHub: תמונת הפרופיל, Sign out.
  2. ב-Android Studio: File > Close Project. במסך הפתיחה, ליד שם הפרויקט ברשימה, לחצו על שלוש הנקודות ובחרו Remove from Recent Projects.
  3. בסייר הקבצים, מחקו את תיקיות הפרויקט (HelloGit ו-HelloGit2). בדרך כלל הן נמצאות ב-C:\Users\...\AndroidStudioProjects.
למה למחוק את הפרויקט?

הוא שמור ב-GitHub, אז לא מאבדים כלום. ובשיעור הבא תקבלו כנראה מחשב אחר, ושם תעשו clone חדש. עותק ישן שנשאר על מחשב הוא מתכון לבלבול: מישהו יפתח אותו ויעבוד על גרסה שכבר לא עדכנית.

סיימתם את השלב כש...

בדיקה של המורה: ב-Settings של GitHub אין חשבון, במנהל האישורים אין שורה עם github, הדפדפן מנותק, ותיקיות הפרויקט נמחקו. 10 נקודות.

1

  2. ב-Classroom, במשימה של המדריך, הדביקו את הקישור והגישו.
מה המורה רואה

המאגר ציבורי, ולכן המורה פותח את הקישור ורואה את כל הקבצים, ואת כל ההיסטוריה: מתי עבדתם, כמה commits עשיתם, ומה כתבתם בכל אחד. הודעות commit טובות הן חלק מהעבודה.
