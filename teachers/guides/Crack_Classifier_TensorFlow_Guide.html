1מבט-על: מה בונים ולמה

הפרויקט מחולק לשני עולמות. ב-Google Colab מאמנים מודל שמבחין בין תמונת בטון סדוק לתמונת בטון תקין ומייצאים אותו לקובץ אחד, crack_classifier.tflite. ב-Android Studio בונים אפליקציה שבוחרת תמונה מהגלריה, מעבירה אותה במודל ומציגה את התוצאה ואת אחוזי הביטחון.

שני העולמות מתחברים דרך חוזה פשוט, ואם מקפידים עליו, כל השאר נופל למקומו:

  • קלט: מערך float32 בגודל [1, 224, 224, 3], צבעי RGB, ערכים בין 0 ל-255, ללא נרמול. הנרמול נעשה בתוך המודל.
  • פלט: מספר אחד, float32 [1, 1]: ההסתברות שבתמונה יש סדק.
  • החלטה: confidence = max(p, 1 − p). אם הביטחון נמוך מ-threshold (כאן 0.90), האפליקציה עונה "לא בטוח".

מה צריך: חשבון Google (בשביל Colab ו-Drive), Android Studio עדכני עם אמולטור (למשל Pixel 8), וכ-5GB פנויים במחשב, בעיקר בשביל מאגר תמונות השטח.

def find_class_dir(root, name):
    for dirpath, dirnames, _ in os.walk(root):
        for d in dirnames:
            if d.lower() == name.lower():
                return os.path.join(dirpath, d)
    raise FileNotFoundError(f"לא נמצאה תיקייה בשם {name} תחת {root}")

EXTS = (".jpg", ".jpeg", ".png")

שלב 3: טעינה ל-tf.data עם augmentation

def load(split, shuffle):
    return keras.utils.image_dataset_from_directory(
        os.path.join(DATA, split), labels="inferred", label_mode="binary",
        class_names=CLASS_NAMES, image_size=(IMG_SIZE, IMG_SIZE),
        batch_size=BATCH, shuffle=shuffle, seed=SEED)

train_ds, val_ds, test_ds = load("train", True), load("val", False), load("test", False)

augment = keras.Sequential([
    layers.RandomFlip("horizontal_and_vertical"),
    layers.RandomRotation(0.1),
    layers.RandomContrast(0.2),
], name="augment")

AUTOTUNE = tf.data.AUTOTUNE
train_ds = train_ds.map(lambda x, y: (augment(x, training=True), y), num_parallel_calls=AUTOTUNE).prefetch(AUTOTUNE)
val_ds = val_ds.prefetch(AUTOTUNE)
test_ds = test_ds.prefetch(AUTOTUNE)
למה ה-augmentation בצינור הנתונים ולא בתוך המודל? כך הוא פועל רק בזמן אימון, והמודל שמיוצא לטלפון נשאר נקי מהשכבות האלה. אחרת שכבות אקראיות עלולות לסבך את ההמרה ל-tflite.

שלב 4: בניית המודל ואימון

לוקחים את MobileNetV2, שכבר אומן על ImageNet, ומקפיאים אותו. מעליו שמים שכבת Dense(1, sigmoid) אחת, ורק היא לומדת. זה transfer learning.

base = keras.applications.MobileNetV2(input_shape=(IMG_SIZE, IMG_SIZE, 3), include_top=False, weights=WEIGHTS)
base.trainable = False

inputs = keras.Input(shape=(IMG_SIZE, IMG_SIZE, 3), name="image")
x = layers.Rescaling(1 / 127.5, offset=-1, name="normalize")(inputs)
x = base(x, training=False)
x = layers.GlobalAveragePooling2D()(x)
x = layers.Dropout(0.2)(x)
outputs = layers.Dense(1, activation="sigmoid", name="p_crack")(x)
model = keras.Model(inputs, outputs, name="crack_classifier")

model.compile(optimizer=keras.optimizers.Adam(1e-3),
              loss="binary_crossentropy",
              metrics=["accuracy", keras.metrics.AUC(name="auc")])
model.summary()
הנקודה החשובה בתא: השכבה Rescaling(1/127.5, offset=-1) ממירה ערכים של 0–255 לטווח שבין 1- ל-1, שבו MobileNetV2 מצפה לקבל את הקלט. מכיוון שהיא נמצאת בתוך המודל, באנדרואיד לא צריך לנרמל: שולחים את ערכי הפיקסלים כמו שהם.
history = model.fit(train_ds, validation_data=val_ds, epochs=EPOCHS,
                    callbacks=[keras.callbacks.EarlyStopping(patience=2, restore_best_weights=True)])

plt.figure(figsize=(10, 4))
for i, m in enumerate(["loss", "accuracy"]):
    plt.subplot(1, 2, i + 1)
    plt.plot(history.history[m], label="train"); plt.plot(history.history["val_" + m], label="val")
    plt.title(m); plt.xlabel("epoch"); plt.legend()
plt.tight_layout(); plt.show()

שלב 5: הערכה ובחירת threshold

from sklearn.metrics import confusion_matrix, classification_report

y_true = np.concatenate([y.numpy().ravel() for _, y in test_ds]).astype(int)
p = model.predict(test_ds, verbose=0).ravel()
y_pred = (p >= 0.5).astype(int)

print(classification_report(y_true, y_pred, target_names=CLASS_NAMES, digits=3, zero_division=0))
print("Confusion matrix (rows=true, cols=pred):")
print(confusion_matrix(y_true, y_pred))

הטבלה הבאה מראה את ההתנגשות בין שני דברים: ככל שה-threshold גבוה יותר, האפליקציה עונה על פחות תמונות (coverage), אבל התשובות שהיא כן נותנת מדויקות יותר.

def threshold_table(p, y_true, thresholds=(0.5, 0.7, 0.8, 0.85, 0.9, 0.95, 0.99)):
    conf = np.maximum(p, 1 - p)
    pred = (p >= 0.5).astype(int)
    print(f"{'threshold':>9} | {'coverage':>8} | {'accuracy (answered)':>19} | {'uncertain':>9}")
    for t in thresholds:
        ans = conf >= t
        acc = f"{(pred[ans] == y_true[ans]).mean():.1%}" if ans.any() else "-"
        print(f"{t:>9.2f} | {ans.mean():>8.1%} | {acc:>19} | {(~ans).sum():>9d}")

threshold_table(p, y_true)

למה בלי quantization? עם Optimize.DEFAULT הקובץ קטן פי 4 (כ-2.5MB במקום כ-9MB), אבל השכבה FULLY_CONNECTED יוצאת בגרסת אופרטור 12. הספרייה tensorflow-lite:2.13.0 באנדרואיד מכירה רק עד גרסה 10, והאפליקציה קורסת עם השגיאה Didn't find op for builtin opcode 'FULLY_CONNECTED' version '12'. בלי quantization כל האופרטורים נשארים בגרסה 1.

בדיקה שהמודל המומר נותן את אותן תשובות כמו מודל ה-Keras:

    from ai_edge_litert.interpreter import Interpreter   # LiteRT, השם החדש של TFLite
except ImportError:
    Interpreter = tf.lite.Interpreter

interp.allocate_tensors()
inp, out = interp.get_input_details()[0], interp.get_output_details()[0]
print("input :", inp["shape"], inp["dtype"])
print("output:", out["shape"], out["dtype"])

imgs, _ = next(iter(test_ds))
diffs = []
for i in range(min(8, imgs.shape[0])):
    x = imgs[i:i + 1].numpy().astype(np.float32)
    interp.set_tensor(inp["index"], x); interp.invoke()
    p_lite = float(interp.get_tensor(out["index"])[0][0])
    p_keras = float(model(x, training=False)[0][0])
    diffs.append(abs(p_lite - p_keras))
print(f"הפרש מקסימלי בין Keras ל-TFLite: {max(diffs):.4f}  (צפוי: מתחת ל-0.02)")

שלוש מסקנות:

  1. דיוק גבוה על ה-test לא מבטיח שהמודל עובד במציאות. הפער של 26 נקודות נובע מהדליפה שתוארה בפרק 2, ומהשוני בין חיתוכים קרובים לתמונות שטח שמראות קיר שלם.
  2. ה-threshold לא פותר את הבעיה. ב-0.99 הדיוק בשטח אפילו יורד. כלומר, הרבה מהטעויות נעשות בביטחון של 99% ומעלה. על תמונות ששונות ממה שהמודל ראה באימון (out-of-distribution), הביטחון שהמודל מדווח לא אומר כמעט כלום על הסיכוי שהוא צודק.
  3. בחירת ה-threshold לאפליקציה: 0.90 הוא פשרה סבירה. האפליקציה עונה על כ-80% מתמונות השטח, ובתשובות שהיא כן נותנת הדיוק כ-77%. הוא לא הופך את המודל לאמין, ולכן האפליקציה מציגה גם הסתייגות.
אם רוצים לשפר את המודל בהמשך: tiling, כלומר חיתוך כל תמונת שטח לאריחים, סיווג של כל אריח וסימון "סדוק" אם אחד מהם סדוק, עוזר כשהטעויות הן סדקים שהמודל פספס. fine-tuning על חלק מתמונות השטח עוזר כשהטעויות הן משטחים תקינים שסווגו כסדוקים. המדריך הזה לא נכנס לשניהם.

7.2 ImageClassifier.java

יוצרים מחלקה חדשה: קליק ימני על com.example.crackclassifier (לא על test ולא על androidTest), New → Java Class → ImageClassifier.

package com.example.crackclassifier;

import android.content.Context;
import android.graphics.Bitmap;

import org.tensorflow.lite.Interpreter;

import java.io.ByteArrayOutputStream;
import java.io.IOException;
import java.io.InputStream;
import java.nio.ByteBuffer;
import java.nio.ByteOrder;

// גרסה ללא ML Model Binding: טוענת את המודל ישירות מתיקיית assets
// ומריצה אותו עם Interpreter. לא תלויה במחלקה CrackClassifier שנוצרת אוטומטית.
public class ImageClassifier {

    // אותו סדר כמו ב-labels.txt: שורה 1 = Negative (תקין), שורה 2 = Positive (סדוק)
    private String[] classes = {"תקין", "סדוק"};

    // מתחת לרמת הביטחון הזו האפליקציה לא מכריעה ומחזירה "לא בטוח"
    private static final float THRESHOLD = 0.90f;
    private static final String MODEL_FILE = "crack_classifier.tflite";

    private Context context;
    private int imageSize = 224;
    private String[] result = new String[2];

    public ImageClassifier(Context context) {
        this.context = context;
    }

    // קורא את קובץ המודל מ-assets לתוך ByteBuffer
    private ByteBuffer loadModel() throws IOException {
        InputStream in = context.getAssets().open(MODEL_FILE);
        ByteArrayOutputStream out = new ByteArrayOutputStream();
        byte[] chunk = new byte[16384];
        int n;
        while ((n = in.read(chunk)) != -1) {
            out.write(chunk, 0, n);
        }
        in.close();
        byte[] bytes = out.toByteArray();
        ByteBuffer buffer = ByteBuffer.allocateDirect(bytes.length);
        buffer.order(ByteOrder.nativeOrder());
        buffer.put(bytes);
        buffer.rewind();
        return buffer;
    }

    public String[] classifyimage(Bitmap bitmap) {
        // convert to a fixed size bitmap (224*224 pixels). true = החלקה (bilinear), כמו באימון
        Bitmap image = Bitmap.createScaledBitmap(bitmap, imageSize, imageSize, true);

        try {
            Interpreter interpreter = new Interpreter(loadModel());

            ByteBuffer byteBuffer = ByteBuffer.allocateDirect(4 * imageSize * imageSize * 3);
            byteBuffer.order(ByteOrder.nativeOrder());

            int[] intValues = new int[imageSize * imageSize];
            image.getPixels(intValues, 0, imageSize, 0, 0, imageSize, imageSize);

            // לא מחלקים ב-255: המודל מנרמל בעצמו ומצפה לערכים 0-255
            int pixel = 0;
            for (int i = 0; i < imageSize; i++) {
                for (int j = 0; j < imageSize; j++) {
                    int val = intValues[pixel++];
                    byteBuffer.putFloat((val >> 16) & 0xFF); // Red
                    byteBuffer.putFloat((val >> 8) & 0xFF);  // Green
                    byteBuffer.putFloat(val & 0xFF);         // Blue
                }
            }
            byteBuffer.rewind();

            // הפלט: מערך [1][1] - ההסתברות לסדק (sigmoid)
            float[][] output = new float[1][1];
            interpreter.run(byteBuffer, output);
            interpreter.close();

            float pCrack = output[0][0];
            float[] confidences = {1 - pCrack, pCrack};

            int maxPos = (pCrack >= 0.5f) ? 1 : 0;
            float maxConfidence = confidences[maxPos];

            if (maxConfidence >= THRESHOLD) {
                result[0] = classes[maxPos];
            } else {
                result[0] = "לא בטוח - נסו לצלם מקרוב יותר";
            }

            String confLevels = "";
            for (int i = 0; i < classes.length; i++) {
                confLevels += String.format("%s: %.1f%%\n", classes[i], confidences[i] * 100);
            }
            result[1] = confLevels;

        } catch (IOException e) {
            result[0] = "שגיאה בטעינת המודל";
            result[1] = e.getMessage();
        }
        return result;
    }
}

שלושה הבדלים מדף ההנחיות של הקהילה, וכולם נובעים מהחוזה שבפרק 1:

  1. אין חלוקה ב-255. המודל מנרמל בעצמו. אם מחלקים, המודל מקבל תמונה כמעט שחורה ומחזיר תשובות שגויות, בלי שום הודעת שגיאה. זו התקלה שהכי קשה לאתר.
  2. פלט אחד ולא שניים. מודל של Teachable Machine מחזיר הסתברות לכל מחלקה (softmax). המודל שלנו מחזיר רק את p, ההסתברות לסדק (sigmoid), ומשלימים ממנו 1 − p.
  3. threshold. מתחת ל-0.90 התוצאה היא "לא בטוח".

שתי הערות על הקוד: createScaledBitmap(..., true) מקטין את התמונה בהחלקה (bilinear), כמו שהוקטנו התמונות באימון. הפונקציה loadModel() קוראת את הקובץ כולו לזיכרון, ולכן היא עובדת גם אם Android דחס את הקובץ בתוך ה-APK.

7.3 MainActivity.java

בנוי לפי דף ההנחיות: ActivityResultCallback<Uri>, GetContent לבחירה מהגלריה, ו-onActivityResult שמעביר את התמונה ל-ImageClassifier.

package com.example.crackclassifier;

import android.graphics.Bitmap;
import android.graphics.BitmapFactory;
import android.net.Uri;
import android.os.Bundle;
import android.view.View;
import android.widget.Button;
import android.widget.ImageView;
import android.widget.TextView;

import androidx.activity.EdgeToEdge;
import androidx.activity.result.ActivityResultCallback;
import androidx.activity.result.ActivityResultLauncher;
import androidx.activity.result.contract.ActivityResultContracts;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

import java.io.FileNotFoundException;

public class MainActivity extends AppCompatActivity implements ActivityResultCallback<Uri> {

    private Button btnGallery;
    private ImageView ivImage;
    private TextView tvResults, tvConfidence;

    private ActivityResultLauncher<String> contentLauncher;
    private ImageClassifier imageClassifier;
    private Bitmap bitmap;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_main);
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });

        btnGallery = findViewById(R.id.btnGallery);
        ivImage = findViewById(R.id.ivImage);
        tvResults = findViewById(R.id.tvResults);
        tvConfidence = findViewById(R.id.tvConfidence);

        btnGallery.setOnClickListener(this::getGalleryPhoto);
        contentLauncher = registerForActivityResult(new ActivityResultContracts.GetContent(), this);
        imageClassifier = new ImageClassifier(this);
    }

    private void getGalleryPhoto(View view) {
        contentLauncher.launch("image/*");
    }

    @Override
    public void onActivityResult(Uri result) {
        if (result != null) {
            ivImage.setImageURI(result); // display image
            try {
                // get bitmap from uri
                bitmap = BitmapFactory.decodeStream(getContentResolver().openInputStream(result));

                // get classification results from the ImageClassifier
                String[] clasified = imageClassifier.classifyimage(bitmap);
                tvResults.setText(clasified[0]);    // chosen category / "לא בטוח"
                tvConfidence.setText(clasified[1]); // confidence levels
            } catch (FileNotFoundException e) {
                throw new RuntimeException(e);
            }
        }
    }
}

10הערות להנחיית מורים

  • הרגע החשוב בפרויקט הוא שלב 7, לא שלב 5. כדאי לתת לתלמידים לחזות מה יהיה הדיוק בשטח לפני שהם מריצים את התא. הפער בין 99.7% ל-73.3% מלמד על הכללה ועל דליפת נתונים יותר מכל הסבר.
  • ה-threshold הוא החלטה הנדסית ולא פרמטר טכני. אפשר לבקש מהתלמידים להצדיק בכתב את הערך שבחרו, לפי הטבלה: כמה תמונות האפליקציה מוכנה להשאיר בלי תשובה, ובשביל כמה דיוק.
  • החוזה בין המודל לאפליקציה הוא נקודת התורפה. חלוקה ב-255, סדר צבעים או גודל תמונה שגוי לא יוצרים שגיאת קומפילציה, רק תשובות שגויות. זו הזדמנות לדבר על בדיקות ועל תיעוד של ממשקים.
  • ההבדל בין המדריך לדף ההנחיות של הקהילה (מודל של Teachable Machine עם softmax ונרמול ל-0–1, לעומת מודל עצמי עם sigmoid ונרמול פנימי) הוא דוגמה טובה לכך שהקוד באפליקציה תלוי במודל שבנינו.
  • הסתייגות באפליקציה: מודל שמדייק ב-77% בשטח לא מתאים להחלטות בטיחות. השורה "כלי עזר לימודי בלבד" בממשק היא חלק מהתוצר ולא קישוט.
